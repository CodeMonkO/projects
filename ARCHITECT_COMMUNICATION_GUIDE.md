# Architect Communication Guide

## Speak Simply

Bad:
> We need to operationalize a holistic AI-native transformation capability.

Good:
> We need a safe way for AI to help teams create, review, and validate software delivery work.

## Explain Architecture Using This Shape

1. What problem exists today?
2. Why it matters
3. Proposed direction
4. What changes for teams
5. What stays under team control
6. Risks
7. First step

## When Talking to Executives

Focus on:
- business value
- speed
- quality
- risk reduction
- cost control
- adoption path

Avoid:
- deep implementation detail
- too many tools
- huge diagrams

## When Talking to Engineers

Focus on:
- boundaries
- APIs
- data flow
- failure modes
- ownership
- implementation details
- tradeoffs

## When Talking to Security

Focus on:
- permissions
- data access
- audit
- tool control
- approval
- misuse cases

## Useful Phrases

- “Let me separate MVP from North Star.”
- “This is the part we should not automate yet.”
- “This is a policy decision, not an LLM decision.”
- “The agent can propose, but the platform should enforce.”
- “This looks simple now, but the failure mode is important.”
- “We need to define ownership before implementation.”
- “The design is good, but the rollback path is not clear yet.”
